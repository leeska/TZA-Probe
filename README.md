# TZA Probe v2

一个独立重建的主机与网络探针：**一个仓库、Server / Agent 两个程序、一个 SQLite 数据库**。后台与公开页全部重新实现，无 Node 构建依赖，无旧主题资产或外部 API 兼容层。

当前为 `2.0.0-dev`，与旧版本独立部署。不接受旧数据库，不迁移旧数据，不覆盖旧服务。

## 功能

- 节点管理、分组、排序、公开开关、单节点密钥轮换。
- CPU / 内存 / 根挂载点磁盘 / 网络速率 / 网卡累计 / 在线状态。
- 30 天分钟级历史，公开面板和管理后台随 Server 嵌入发布。
- 浅色 / 深色主题：默认跟随系统，页面右上角与后台侧栏可手动切换，偏好保存在浏览器本地。
- 显式节点绑定的 IPv4 / IPv6 TCP 延迟与三网回程任务。
- 回程标签按实际经过的骨干命名（163 / CN2GIA / CN2GT / 4837 / 9929 / 10099 / CMIN2 / CMI / CTG）；ASN 优先，前缀兜底，因此工具没解析出 ASN 的跳（例如 59.43.* 的 CN2 跳）仍能识别。CN2 直接进入 59.43.* 记为 CN2GIA，先经过 163（202.97.*、219.141.* 等 163 段或 AS4134）再进入记为 CN2GT；表外前缀保持“未知”。
- 卡片按运营商分格展示：TCP 延迟为电信 / 联通 / 移动 / 其他四格，三网回程为电信 / 联通 / 移动三格；两者的地区分别由后台的“卡片延迟地区”和“卡片代表地区”指定，延迟地区留空时沿用代表地区。点击也有分工：点某个延迟格只看该运营商的 TCP 延迟趋势，点某个回程格只看该运营商的回程路径（含脱敏跳表），点卡片其它位置才打开含主机历史的综合信息；聚焦视图里的“查看全部信息”可随时切回综合信息。
- 月度计费周期、流量额度、四种流量计费方式、价格、到期日期。
- 续费 / 流量 / 持续 CPU 或内存负载 / 离线提醒，触发与恢复事件、Telegram / Webhook 和有限重试。

## 快速运行

需要 Go 1.25 或更新版本。不需要 CGO、外部数据库或 Node。

```sh
go build -o bin/tza-server ./cmd/server
go build -o bin/tza-agent ./cmd/agent
./bin/tza-server --listen 127.0.0.1:25774 --data ./data
```

访问 `http://127.0.0.1:25774/admin`，使用 `data/admin-token` 中的密钥登录。也可以设置 `TZA_ADMIN_TOKEN`（至少 32 个字符）；密钥不会写入日志。新增节点后，“接入”弹窗给出一条 `curl ... | sh -s -- --endpoint ... --token ...` 命令，在 Agent 主机执行即可自动下载、配置并启动 Agent（见 docs/DEPLOYMENT.md）。接入配置中的地址必须能从 Agent 主机访问；另一台机器不能使用 `127.0.0.1` 或 `localhost` 连接此 Server。也可以下载 `agent.json` 手动运行：

```sh
chmod 600 agent.json
./bin/tza-agent --config agent.json
```

配置示例（令牌从后台创建节点获得）：

```json
{
  "endpoint": "https://probe.example.com",
  "token": "后台生成的64位节点密钥",
  "interfaces": ["eth0"],
  "mount": "/",
  "nexttrace": "",
  "geo_provider": "",
  "trace_method": "",
  "allow_http": false
}
```

`interfaces` 为空时汇总非 loopback 网卡。有桥接、容器、隧道的机器应明确填写公网网卡，防止重复计数。`mount` 指定一个文件系统；不会把重复挂载点相加。正式支持和发布目标是 Linux amd64 / arm64，本地 macOS 可用于开发验证。

## 三网探测

后台创建任务，可从内置目录选择地区、运营商和 IP 协议，再明确选择节点。空绑定不执行。回程最短 15 分钟、默认 1 小时；TCP 最短 30 秒。单个节点最多同时执行一个 TCP 和一个回程任务。

回程由 Agent 内置的 **NTrace-core**（NextTrace 的同一个追踪核心）在进程内执行，无需在节点上安装任何外部工具；固定 24 跳、单次测量、1500 毫秒超时和 45 秒预算，显式关闭路径地图生成，避免上传完整路径制作分享地图。`nexttrace` 留空即用内置实现；填写绝对路径则改为调用该外部二进制（仅作运维兜底）。`trace_method` 是探测方式，默认 `icmp`（与 NextTrace CLI 一致），可改 `tcp` 或 `udp`。`geo_provider` 选择跳数 ASN/地区数据源，留空等同上游默认 `NextTrace-API`，也可填 `IPAPI.com`、`disable-geoip` 等；`disable-geoip` 时标签完全依赖本地地址前缀表。权限不足、目标不响应或数据源不可用时不会编造线路。运行原始套接字探测时，使用具备所需权限的服务账户或由运维为工具配置对应能力。

线路依据实际 ASN 与跳地址前缀展示 `163`、`CN2GIA`、`CN2GT`、`CTG`、`10099`、`9929`、`4837`、`CMIN2`、`CMI` 及路径组合；前缀表沿用同族分类器的三网回程网段，只覆盖各运营商骨干网段，表外地址不会硬猜。ASN 数据源由 Agent 直接请求（可用 `geo_provider` 指定或关闭），页面与 Server 不执行 traceroute，也不请求 ASN 服务。内置追踪核心 NTrace-core 为 GPL-3.0，Agent 二进制的分发条款见 NOTICE。

若系统 DNS 返回 `198.18.0.0/15` Fake-IP，Agent 会拒绝把代理虚拟地址当作真实目标并标记原因。请在具备直接网络出口的节点运行，或由运维明确配置正确解析；程序不会自行修改系统代理。

同一原因，**开着代理（尤其 Fake-IP）的机器不能用来验收回程**：探测从 Agent 所在主机发出，若默认路由指向本机代理，跳数与 ASN 反映的是代理转发路径，不是该节点的运营商线路。此类结果在面板上看不出区别，但线路标签无意义；回程验收请在具备直连出口的节点上做。

目标目录为 2026-09-18 从公开源刷新的 186 个明确 IP 快照，已验证地址族和公网地址格式；不使用已失效的旧域名别名，也不依赖 Agent 的 DNS 解析目录目标。源提供的 IP 不代表可达性保证，应在实际节点验证。维护时可显式运行 `scripts/refresh-catalog.py`（支持 `--input 已下载.tsv`），Server/Agent 不自动拉取目录。部署后应验证需要的目标；一个任务可同时勾选延迟和回程，按地区与运营商搜索目录并批量选择；海外自定义目标可选择“其他”运营商。IP 协议按目标组独立设置：上方的 IPv4 / IPv6 是新加入目标的默认值并可一键套用到全部已选，每组再在“已选目标”上单独改成只测 IPv4、只测 IPv6 或两者都测；目录里没有对应地址的协议不可勾选，每组至少保留一种。节点的“卡片代表地区”须与对应任务地区一致。每运营商有多个同地区同协议任务时，卡片采用最新一次结果，详情展示全部。

TCP 指标是连接耗时和连接失败比例，**不声称是 ICMP 丢包率**。卡片的每个运营商格取该地区同运营商全部目标的平均延迟；每格下方是 20 个小格，**每个小格是一次探测的结果**，最右是最新一次、左侧是更早的探测，格数不足时左边留空。格子按那次结果的大小落在 20 档无级色带上（绿 → 青 → 黄 → 橙 → 红），所以一格的颜色说明的是"那一次"有多快；失败的那一次画成空心红格，与"没有数据"的灰格区分开，每格悬停显示那次的时间与数值。有结果但全部失败时显示“超时”，没有对应任务时显示“未检测”，成功次数与最近检测时间在格子行的悬停提示里。目录外的自定义目标（以及没有运营商的旧任务）归入“其他”。节点详情提供 CPU、内存、上下行速率历史，以及按目标和 IPv4 / IPv6 分开的 TCP 延迟、连接失败率历史。可选 1 小时、24 小时、7 天；主机历史还可查看 30 天，网络历史最多保留 7 天。

## 计费与提醒

- 周期按 **UTC 每月指定日 00:00** 重置；当月不足指定日期时取月末。
- 额度 GB 使用十进制字节。支持双向合计、取较大方向、仅下载、仅上传。
- 首次上报建立基线，不计入接入前流量。计数器重置或主机重启重新建立基线，不把旧累计重复计费。
- 流量是采样差值，跨周期的离线间隔按恢复上报日归属；重启前未上报部分无法恢复。因此它是运维估算，不能替代服务商账单。
- Agent 上报计数器来源标识；主机启动或网卡集合变化时自动重建流量基线，不回填历史用量。
- 周期账本保存 400 天，独立于 30 天主机曲线；网络任务结果保存 7 天，告警事件保存 90 天。
- 负载达到任一阈值且持续超过设置时间才触发。离线提醒可额外等待；默认每次条件进入/解除各记录一次，可选至少 5 分钟的重复提醒间隔，0 表示不重复。
- Webhook 接收 `{ "version": 1, "event": { ... } }`，成功状态为 HTTP 2xx。失败指数退避、最多 10 次，每轮最多 5 条；接收端按 `event.id` 去重。未配置出口时保留事件，配置后补发未投递事件。
- 通知采用至少一次投递语义，后台显示投递状态和最近失败原因。通知恢复事件也可能来自关闭提醒规则。
- 后台“告警与通知”选择 Telegram，填写 Bot Token 和 Chat ID；各节点的提醒开关与阈值在节点编辑页设置。同一时间使用一个通知渠道。
- 可手动校正当前周期已用流量，后续增量继续累计，下周期自动失效。修改重置日或统计方向会清除校正。续费后在节点编辑页更新到期日期。

网络任务支持暂停 / 恢复、立即安排执行、复制和批量绑定节点。暂停不取消已领取的探测，重新绑定保留历史；编辑检测目标会清除旧结果。执行记录显示当前绑定节点各已执行目标的最近时间与失败原因。
