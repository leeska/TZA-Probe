# TZA Probe v2

一个独立重建的主机与网络探针：**一个仓库、Server / Agent 两个程序、一个 SQLite 数据库**。后台与公开页全部重新实现，无 Node 构建依赖，无旧主题资产或外部 API 兼容层。

当前为 `2.0.0-dev`，与旧版本独立部署。不接受旧数据库，不迁移旧数据，不覆盖旧服务。

## 功能

- 节点管理、分组、排序、公开开关、单节点密钥轮换。
- CPU / 内存 / 根挂载点磁盘 / 网络速率 / 网卡累计 / 在线状态。
- 30 天分钟级历史，公开面板和管理后台随 Server 嵌入发布。
- 浅色 / 深色主题：默认跟随系统，页面右上角与后台侧栏可手动切换，偏好保存在浏览器本地。
- 显式节点绑定的 IPv4 / IPv6 TCP 延迟与三网回程任务。
- 回程标签按实际经过的骨干命名（163 / CN2GIA / CN2GT / 4837 / 9929 / 10099 / CMIN2 / CMI / CTG）；ASN 优先，前缀兜底，因此工具没解析出 ASN 的跳（例如 59.43.* 的 CN2 跳）仍能识别。电信线路按中国侧落地点判定：CN2 跳之后仍走 59.43.* 到目标省份记为 CN2GIA，转回 163 骨干（202.97.*）落地记为 CN2GT。AS4134 是电信自营网段，国际入口、省级接入与 163 骨干共用这个 ASN（实测 218.30.0.0/15、110.184.0.0/13 都属 AS4134），所以裸 AS4134 不足以判定 163 骨干；一条电信线路只给一个标签：同时看到 CTG 与 CN2 跳时按 CTG 计（CTG 是这条路径的产品，59.43.* 只是它的承载），接入网也不会另记一个 163。移动同理：CMI（AS58453）与 CMIN2（AS58807）同属中移国际，一条移动线路也只给一个标签，两者同时出现时按 CMIN2 计；中国移动自营的 AS9808 与 2409:* 是落地接入侧，不记成中移国际（注册库里 221.183.*、111.24.*、111.13.*、2409:8080:* 的归属就是 AS9808），223.120.* 上下两半分属 CMIN2 与 CMI、脱敏后无法区分，所以不进前缀表。表外前缀保持“未知”。
- 卡片按运营商分格展示：TCP 延迟为电信 / 联通 / 移动 / 其他四格，三网回程为电信 / 联通 / 移动三格；两者的地区分别由后台的“卡片延迟地区”和“卡片代表地区”指定，延迟地区留空时沿用代表地区。点击也有分工：点某个延迟格只看该运营商的 TCP 延迟趋势，点某个回程格只看该运营商的回程路径（含脱敏跳表），点卡片其它位置才打开含主机历史的综合信息；聚焦视图里的“查看全部信息”可随时切回综合信息。
- 公开面板、节点管理与任务目录的搜索同时认中文、全拼、拼音首字母、英文和代号：香港 = 香港 / xianggang / xg / hk / hongkong，电信 = 电信 / dianxin / dx / ct / telecom，目录里按空格分隔多个词是「且」的关系（如 `hb ct`）。首字母可能撞名（`hb` 同时是河北与湖北），要精确就用全拼。拼音表在 `web/pinyin.js`，由 `scripts/gen-pinyin.mjs` 生成（多音字地名按词定音，重庆 = chongqing）；表外的汉字退回纯文本匹配。搜索框里贴目录地址同样能筛出对应目标。
- 月度计费周期、流量额度、四种流量计费方式、价格、到期日期。
- 续费 / 流量 / 持续 CPU 或内存负载 / 离线提醒，触发与恢复事件、Telegram / Webhook 和有限重试。
- MCP 接口 `/mcp`：AI 客户端用同一个管理密钥读写整站——节点与任务的增删改、接入密钥轮换、用量校正、任务绑定与暂停/执行、通知出口与测试通知，另有面板没有的目录检索与执行记录查询。读工具与写工具分开标注（`readOnlyHint` / `destructiveHint`），写工具每次返回被改对象的 id。

## 一键部署

Linux 主机（amd64 / arm64），一条命令装成 systemd 服务：

```sh
curl -fsSL https://raw.githubusercontent.com/leeska/TZA-Probe/main/deploy/install.sh | sudo sh
```

脚本拉取当前 `main` 源码构建（需要 Go 1.27 与 git），安装 `/usr/local/bin/tza-server` 与 systemd 单元，建好 `/var/lib/tza-probe`，把 amd64 / arm64 两个 Agent 一并放进数据目录，最后打印登录地址与密钥位置。重复执行即升级：旧二进制保留为 `tza-server.previous`，数据目录不动。可选参数：`--version vX.Y.Z` 改用 GitHub Release（免 Go 与 git）、`--listen ADDR`、`--data DIR`、`--no-systemd`。

装完访问 `http://127.0.0.1:25774/admin`，密钥在 `/var/lib/tza-probe/admin-token`。跨主机接入请在前面配置 HTTPS 反代，见 [部署说明](docs/DEPLOYMENT.md)。

Docker 部署（镜像本地构建，数据放命名卷）：

```sh
git clone --depth 1 https://github.com/leeska/TZA-Probe && cd TZA-Probe
docker compose -f deploy/docker-compose.yml up -d --build
```

被监控主机不需要装 Go：在后台新增节点后，“接入”弹窗给出的 `curl ... | sh -s -- --endpoint ... --token ...` 命令会自动下载并启动 Agent。

## 快速运行

本地预览用源码直接跑，需要 Go 1.27（更旧的 Go 会自动下载 go.mod 指定的工具链）。不需要 CGO、外部数据库或 Node。

```sh
go build -o bin/tza-server ./cmd/server
go build -o bin/tza-agent ./cmd/agent
./bin/tza-server --listen 127.0.0.1:25774 --data ./data
```

访问 `http://127.0.0.1:25774/admin`，使用 `data/admin-token` 中的密钥登录。也可以设置 `TZA_ADMIN_TOKEN`（至少 32 个字符）；密钥不会写入日志。新增节点后，“接入”弹窗给出一条 `curl ... | sh -s -- --endpoint ... --token ...` 命令，在 Agent 主机执行即可自动下载、配置并启动 Agent（见 docs/DEPLOYMENT.md）。接入配置中的地址必须能从 Agent 主机访问；另一台机器不能使用 `127.0.0.1` 或 `localhost` 连接此 Server。也可以下载 `agent.json` 手动运行：

```sh
chmod 600 agent.json
./bin/tza-agent --config agent.json
```

配置示例（令牌从后台创建节点获得）：

```json
{
  "endpoint": "https://probe.example.com",
  "token": "后台生成的64位节点密钥",
  "interfaces": ["eth0"],
  "mount": "/",
  "nexttrace": "",
  "geo_provider": "",
  "trace_method": "",
  "allow_http": false
}
```

`interfaces` 为空时汇总非 loopback 网卡。有桥接、容器、隧道的机器应明确填写公网网卡，防止重复计数。`mount` 指定一个文件系统；不会把重复挂载点相加。正式支持和发布目标是 Linux amd64 / arm64，本地 macOS 可用于开发验证。

## 三网探测

后台创建任务，可从内置目录选择地区、运营商和 IP 协议，再明确选择节点。空绑定不执行。回程最短 15 分钟、默认 1 小时；TCP 最短 30 秒。单个节点最多同时执行一个 TCP 和一个回程任务。

回程由 Agent 内置的 **NTrace-core**（NextTrace 的同一个追踪核心）在进程内执行，无需在节点上安装任何外部工具；固定 24 跳、单次测量、1500 毫秒超时和 45 秒预算，显式关闭路径地图生成，避免上传完整路径制作分享地图。`nexttrace` 留空即用内置实现；填写绝对路径则改为调用该外部二进制（仅作运维兜底）。`trace_method` 是探测方式，默认 `icmp`（与 NextTrace CLI 一致），可改 `tcp` 或 `udp`。`geo_provider` 选择跳数 ASN/地区数据源，留空等同上游默认 `NextTrace-API`，也可填 `IPAPI.com`、`disable-geoip` 等；`disable-geoip` 时标签完全依赖本地地址前缀表。权限不足、目标不响应或数据源不可用时不会编造线路。运行原始套接字探测时，使用具备所需权限的服务账户或由运维为工具配置对应能力。

线路依据实际 ASN 与跳地址前缀展示 `163`、`CN2GIA`、`CN2GT`、`CTG`、`10099`、`9929`、`4837`、`CMIN2`、`CMI` 及路径组合；前缀表沿用同族分类器的三网回程网段，只覆盖各运营商骨干网段，表外地址不会硬猜。ASN 数据源由 Agent 直接请求（可用 `geo_provider` 指定或关闭），页面与 Server 不执行 traceroute，也不请求 ASN 服务。内置追踪核心 NTrace-core 为 GPL-3.0，Agent 二进制的分发条款见 NOTICE。

若系统 DNS 返回 `198.18.0.0/15` Fake-IP，Agent 会拒绝把代理虚拟地址当作真实目标并标记原因。请在具备直接网络出口的节点运行，或由运维明确配置正确解析；程序不会自行修改系统代理。

同一原因，**开着代理（尤其 Fake-IP）的机器不能用来验收回程**：探测从 Agent 所在主机发出，若默认路由指向本机代理，跳数与 ASN 反映的是代理转发路径，不是该节点的运营商线路。此类结果在面板上看不出区别，但线路标签无意义；回程验收请在具备直连出口的节点上做。

Agent 判定“这台机器支持哪个 IP 协议”时不只看接口地址，还要求内核真有该族的路由：只把 IPv4 交给本机代理或隧道（WARP 之类）、系统里没有 IPv4 默认路由的机器，接口上仍留着 `172.16.0.2` 这样的地址，但任何 IPv4 拨号都会立刻 `network is unreachable`。这种协议不再上报，对应任务也不再派发到该节点，面板只显示真正出得去的协议，而不是把 100% 连接失败当成线路质量。

目标目录为 2026-09-18 从公开源刷新的 186 个明确 IP 快照，已验证地址族和公网地址格式；不使用已失效的旧域名别名，也不依赖 Agent 的 DNS 解析目录目标。源提供的 IP 不代表可达性保证，应在实际节点验证。维护时可显式运行 `scripts/refresh-catalog.py`（支持 `--input 已下载.tsv`），Server/Agent 不自动拉取目录。部署后应验证需要的目标；一个任务可同时勾选延迟和回程，按地区与运营商搜索目录并批量选择；海外自定义目标可选择“其他”运营商。节点地区与自定义目标地区都可以自由填写，建议列表除了目录里的省份，还内置香港、台湾、日本、韩国、新加坡、美国、英国、德国等常用海外地区，节点放在海外时不必手打。IP 协议按目标组独立设置：上方的 IPv4 / IPv6 是新加入目标的默认值并可一键套用到全部已选，每组再在“已选目标”上单独改成只测 IPv4、只测 IPv6 或两者都测；目录里没有对应地址的协议不可勾选，每组至少保留一种。节点的“卡片代表地区”须与对应任务地区一致。每运营商有多个同地区同协议任务时，卡片采用最新一次结果，详情展示全部。

TCP 指标是连接耗时和连接失败比例，**不声称是 ICMP 丢包率**。卡片的每个运营商格取该地区同运营商全部目标的平均延迟；每格下方是 20 个小格，**每个小格是一次探测的结果**，最右是最新一次、左侧是更早的探测，格数不足时左边留空。格子按那次结果的大小落在 20 档无级色带上（绿 → 青 → 黄 → 橙 → 红），所以一格的颜色说明的是"那一次"有多快；失败的那一次画成空心红格，与"没有数据"的灰格区分开，每格悬停显示那次的时间与数值。有结果但全部失败时显示“超时”，没有对应任务时显示“未检测”，成功次数与最近检测时间在格子行的悬停提示里。目录外的自定义目标（以及没有运营商的旧任务）归入“其他”。节点详情提供 CPU、内存、上下行速率历史，以及按目标和 IPv4 / IPv6 分开的 TCP 延迟、连接失败率历史。可选 1 小时、24 小时、7 天；主机历史还可查看 30 天，网络历史最多保留 7 天。

## 计费与提醒

- 周期按 **UTC 时刻逐月重置，精确到秒**（例如 `2026-09-01 00:00:00`）；当月不足该日时取月末。表单给出「本月 1 日」作为默认值，填 `YYYY-MM-DD HH:MM:SS`。
- 额度 GB 使用十进制字节。支持双向合计、取较大方向、仅下载、仅上传。
- 首次上报建立基线，不计入接入前流量。计数器重置或主机重启重新建立基线，不把旧累计重复计费。
- 流量是采样差值，跨周期的离线间隔按恢复上报日归属；重启前未上报部分无法恢复。因此它是运维估算，不能替代服务商账单。
- Agent 上报计数器来源标识；主机启动或网卡集合变化时自动重建流量基线，不回填历史用量。
- 周期账本保存 400 天，独立于 30 天主机曲线；网络任务结果保存 7 天，告警事件保存 90 天。
- 负载达到任一阈值且持续超过设置时间才触发。离线提醒可额外等待；默认每次条件进入/解除各记录一次，可选至少 5 分钟的重复提醒间隔，0 表示不重复。节点编辑页在每个提醒字段上标注默认值（离线等待 60 秒、续费提前 7 天、流量 80%、CPU/内存 90%、负载持续 300 秒、重复间隔 0），新建节点即按这些值预填。
- Webhook 接收 `{ "version": 1, "event": { ... } }`，成功状态为 HTTP 2xx。失败指数退避、最多 10 次，每轮最多 5 条；接收端按 `event.id` 去重。未配置出口时保留事件，配置后补发未投递事件。
- 通知采用至少一次投递语义，后台显示投递状态和最近失败原因。通知恢复事件也可能来自关闭提醒规则。
- 后台“告警与通知”选择 Telegram，填写 Bot Token 和 Chat ID；各节点的提醒开关与阈值在节点编辑页设置。同一时间使用一个通知渠道。
- 可手动校正当前周期已用流量，后续增量继续累计，下周期自动失效。修改重置时间或统计方向会清除校正。续费后在节点编辑页更新到期时间（UTC，精确到秒）。

网络任务支持暂停 / 恢复、立即安排执行、复制和批量绑定节点。暂停不取消已领取的探测，重新绑定保留历史；编辑检测目标会清除旧结果。执行记录显示当前绑定节点各已执行目标的最近时间与失败原因。

## MCP 接口

Server 在 `POST /mcp` 上提供 [Model Context Protocol](https://modelcontextprotocol.io) 端点：用同一个管理密钥鉴权（请求头携带管理密钥，或面板会话 Cookie），工具覆盖管理面板的全部操作——读取节点、任务、主机历史、TCP 延迟与回程标签，以及新建 / 修改 / 删除节点与任务、轮换接入密钥、校正用量、绑定与暂停任务、配置通知出口并发送测试通知。写工具与面板走同一套持久化与校验：非法输入按 `-32602` 报错，周期已变化这类冲突按工具错误返回；返回体只给 id、状态与接入命令，已存的 Bot Token / Webhook 不回显。

客户端配置（通用的 `mcpServers` 写法）：

```json
{ "mcpServers": { "tza-probe": { "type": "http", "url": "https://probe.example.com/mcp", "headers": { "Authorization": "Bearer 管理密钥" } } } }
```

任何支持 HTTP 端点或 `mcpServers` 配置的客户端填同一个 URL 与管理密钥即可，改完重载客户端。

工具 21 个。读取：`list_nodes`、`list_tasks`、`node_history`（主机历史 1–720 小时）、`node_network_history`（网络历史 1–168 小时）、`node_observations`（每个检测项最新结果，含回程标签）、`recent_events`、`latency_samples`、`list_catalog`（内置目标目录，可按地区 / 运营商 / 协议过滤）、`task_runs`、`get_settings`。写入：`create_node`、`update_node`、`delete_node`、`rotate_node_token`、`correct_node_traffic`、`create_task`、`update_task`、`delete_task`、`control_task`（暂停 / 恢复 / 立即安排 / 绑定节点）、`update_settings`、`test_notification`。`update_node` / `update_task` 是合并语义：只提交要改的字段，没提到的字段保持原值（`alerts` 这类嵌套对象按字段合并，不必整段覆盖）。回程跳地址与管理接口同样脱敏，过期或失败的探测不返回线路标签。

同一个地址同时说两代协议：`2026-07-28`（无握手，版本与客户端信息按请求放在 `_meta` 并镜像到 `MCP-Protocol-Version` / `Mcp-Method` / `Mcp-Name` 头）与 `2025-11-25` / `2025-06-18`（`initialize` 握手）。版本不认识时返回 `UnsupportedProtocolVersionError` 并列出支持的版本，头与请求体不一致时按规范返回 `HeaderMismatch`。协议细节见 [HTTP 协议](docs/API.md)。
