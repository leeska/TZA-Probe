# 节点插件与按需安装

> 当前产品模型以 [普通插件管理](PLUGIN-MANAGEMENT.md) 为准：先安装主控管理部分，
> 再在同一插件详情的 Agent 页按需安装组件。不再提供独立的「节点插件」分类或身份填写表单。
> 以下记录保留早期阶段设计与验收证据，不代表当前页面结构。
> 安装通道现已合入 Agent；下述「休眠助手」方案已被单进程实现取代，默认允许、可按节点关闭。

## 目标

用户只安装 TZA Agent，在「插件 → 市场 → 节点插件」选择 IPSentinel 和目标节点。
未启用时不下载 Python、Chromium 或运行时，不启动执行器或专用常驻管理进程。
Agent 只增加少量管理代码，不能承诺二进制体积、内存或处理开销严格为零。

节点插件与主控通知/目标集插件共享市场入口，但不能共享代码执行权限。
节点插件继续使用独立 `executor.json`、签名和精确制品摘要；不能伪装成 `plugin.json`，
也不能通过主控插件 ZIP 上传或普通市场安装接口运行代码。

## 分阶段交付

1. **市场入口与节点计划**：展示节点插件、选择精确版本和多个节点；只向已有本机授权安装通道的
   节点申请计划。未授权、状态过期或有活动请求的节点不可选择。提交时再次在事务中核对节点
   配置范围，配置变化必须重新选择。逐节点显示成功或失败；成功项不重复提交。
2. **首次安装与休眠助手**：普通 Agent 安装/升级流程部署固定、经审核的本机安装助手及唤醒入口，
   默认关闭节点插件权限。管理员明确允许后，复用心跳传递有限指令，按需唤醒助手；
   不增加禁用状态的轮询服务，不给普通 Agent 放宽沙箱，不允许任意命令、路径或下载地址。
   老 Agent 没有此能力时明确要求升级，不能默默扩大权限。
3. **首次启用与停用编排**：生成绑定、配置、普通运行用户与受限服务；安装、首次本机 adopt、
   启动验收、托管授权分别记账。UI 可以串成向导，不能省略内部批准和隔离检查。
   停用先阻止新任务、排空并确认记录 ACK，再停止进程；未知状态保留人工核对入口。
   保留历史和缓存；卸载依赖、删除历史、销毁 Profile 必须分别明确确认。

第一阶段不声称完成第二、三阶段。现有通道仍需本机预配专用安装服务，
市场按钮是「选择节点 / 生成安装计划」，不是已经可用的一键启用。
首次 adopt 仍是 IPSentinel 本机 CLI 操作；下一阶段需要与权威 handoff 对齐并增加集成测试，
不能扩充 UDS RPC 或用远程 Shell 绕过契约。

## 默认与信任边界

- 打开市场只读取声明元数据，不请求依赖制品、不启动节点进程。
- 选择节点生成计划只取得签名声明；节点独立检查信任公钥、平台、版本和权限。
- 管理员看到实际下载大小、制品摘要、资源/权限范围后批准，节点才下载依赖。
- 市场的 `compatible` 仅表示 Probe 版本兼容，不代表 OS、Agent、cgroup 或宿主库验收通过。
- 安装通道的本机信任配置是最终约束；中控展示的 CC 目录不是节点安装授权。
- 不按远端清单下载任意 postinstall/helper，不把 root 权限交给插件。
- 普通 Agent 运行指标、心跳和普通探测；浏览器仍在独立非 root、cgroup 隔离进程运行。
- 旧 epoch、旧配置范围、过期批准不可复用；断线重试先查原请求，不能重复执行安装。

## 验证门槛

市场和 API 测试覆盖 executor 不能进入主控安装器、匿名/跨站拒绝、
未知版本/非官方包拒绝、节点范围变更、并发请求冲突及部分失败后的重试。
浏览器验证节点选择、错误提示、无兼容/未授权节点、390px 布局。
后续首次启用必须在 Linux 验证禁用时无额外进程/依赖下载、非 root peer、
Chromium、断网、重启恢复、停用与卸载保留数据；不可用 fixture 代替生产运行验收。
