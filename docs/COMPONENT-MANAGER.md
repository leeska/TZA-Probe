# Agent 组件管理器：内部操作契约

状态：2026-11-08 公共操作收敛与组件宿主已接入现有 Agent；
共享资源准入和服务进程监督已接入正常 Agent 路径；跨执行方式的任务监督及组合流程仍在实施。
公共管理器只运行 Agent 内置注册的可信适配器，
不接受包提供的可执行回调、Shell、宿主路径或新增远程执行权限。

## 操作收敛

公共操作管理器复用既有节点连接及私有回执存储，负责以下顺序：

1. 对同一组件实例取操作锁，读取未确认记录。
2. 优先使用记录原登记作用域补传；确认前不刷新作用域。
3. 重启后遇到执行中记录，转为结果未知；不再次执行原操作。
4. 计划阶段只调用适配器规划，不执行未批准操作。
5. 批准必须在有效期内，且适配器验证精确计划及原作用域。
6. 执行前重新规划，比对原批准；适配器准入通过后再次核对批准有效期，
   主控确认操作仍有效后，先同步本机执行中记录。
7. 执行并校验适配器业务回执。中断或无法证明的结果标记未知，等待只读核对。
8. 结果先落盘再投递，确认后归档；断线保留原身份和记录。

公共层使用 `requested`、`awaiting_approval`、`approved`、`running`、`unknown`
和 `failed` 作为共同阶段。各组件成功终态保留自己的语义，
例如 `installed`、`selected`、`drained` 或 `enabled`，由适配器验证。
节点、组件实例、操作和逻辑任务分别标识；不得用重新生成操作 ID 代替恢复。

适配器负责登记校验、请求到公共元信息的映射、计划和回执校验、
已批准请求的预检形式、精确计划比较、原协议序列化以及执行/核对。
来源和网络错误保留类型，不能将执行后连接丢失改报为“尚未执行”。
公共层只负责顺序与恢复，不自行批准、扩权或解释业务结果。

## 并存与调度

组件实例具有稳定注册键和独立状态目录。公共宿主管理不同实例的循环、
超时、取消和退出等待；某个实例失败或暂停不取消其他实例及 Agent 心跳。
暂停只停止新的管理调用；已开始操作必须按原协议完成或持久保留未知结果，
不能仅关闭协程便宣称外部进程已停止。

资源准入采用节点共享容量、实例配额及每个操作的资源需求交集，
同一操作的重复准入不能造成重复执行。
进程及内核限制仍须由可信执行适配器实际施加；预约额度不等于已隔离。
无法确认清理时保留诊断状态，不能提前回收可能仍使用的资源。

## 已接入的实现

- `componentmanager.Installer` 承接原安装通道的锁、审批、预检、执行前持久化、
  原作用域补传和未知结果核对。`executorruntime.ChannelProtocol` 保留专有协议映射与校验；
  `RuntimeInstaller` 是原 Go API 的兼容包装。
- `componentmanager.Manager` 注册稳定组件/实例键，拒绝重复键、重叠或别名状态目录。
  各实例的安装与记录活动独立定时、超时、取消，并在关闭时等待全部活动结束。
  未完成清理的活动保持 running，不能恢复第二个活动或误报已经停止。
- 正常 Agent 的 IPSentinel 安装和记录循环已注册到公共宿主，
  不再由 IPSentinel 专有循环管理两条协程。专有配置、服务参数和业务协议由
  `ipsentinelSession` 适配；旧安装身份及目录不变。
- 声明式注册不要求 UUID、状态目录或进程，且禁止附加节点活动及执行能力。
  当前注册在宿主运行期间固定，不引入远程动态注册任意代码。
- `componentprocess.Service` 共用非 root 服务、私有状态、CPU/内存/进程外层限制、
  地址族范围及按需 cgroup 委托。IPSentinel 保持原 640 MiB / 100% CPU / 384 进程上限；
  无浏览器组件可以使用自己的范围，无需 Python 或 Chromium。
- `componentprocess.LocalControl` 只支持注册服务的定义、状态、启动和停止，
  并提供固定属性的进程清理检查，使用受保护 systemctl、有界输出及超时。适配器仍负责精确服务名、
  已批准定义摘要和生命周期前置条件；不是远程任意服务控制入口。
- `componentresource` 提供惰性创建的节点共享容量池和版本化持久账本。
  正常 Agent 在启用/激活前及新业务提交/恢复前登记实例的外层限制；
  资源等待保留原批准和操作 ID，不先标记执行中，不阻塞记录补传、原任务查询、取消和暂停。
  容量同时受宿主及父 cgroup 的内存、CPU、进程数约束，并保留 Agent 的基本余量。
- `ServiceSupervisor` 将同一实例的启动、停止和回收串行化，
  不阻塞其他实例。启动返回未知或无法核实清理时保留预留；
  停止后检查主/控制进程、KillMode 以及整个 cgroup 子树，确认后才回收容量。
  关闭容量池等待在途生命周期结束，再释放进程锁。
  具体文件格式与边界见 [节点共享资源准入](COMPONENT-RESOURCES.md)。

`Manager.Pause` 停止的是管理活动，不等同业务停用或卸载。
业务停用还需按适配器协议收敛任务与进程；
G04 必须把这些步骤接入同一用户入口，不能仅调用 Pause 便显示业务已停止。

外层服务定义的公共抽取不自动改写已部署旧服务。
正常宿主在任何组件活动开始前，先清查全部已注册固定服务的内核资源上限，
按物理服务身份补登记已运行实例，周期性复核失败会阻止新准入但不阻塞活动收敛。
观察到 inactive 不回收潜在在途启动预留；仍需明确的停止与进程清理证据。
同一宿主拒绝独立的容量池及重复的物理服务登记。
旧独立安装器、手工 Socket 接入和原生探测还未全部迁移到共享容量池，
不能据正常插件路径接入便声称所有执行入口已统一。
旧服务迁移、跨执行方式的逻辑任务监督和完整组合流程仍需继续实现及验收。
`componenttask.Broker` 已接入 IPSentinel 的原任务查询、受理及取消；
公共层先查询原逻辑 ID，再由适配器判断是否明确未知、是否有资格及窗口是否仍有效。
原任务、请求和投递尝试分开，提交或取消回复丢失后均以原 ID 恢复。
公共代码不依赖业务 Profile 或 epoch，也不创建额外预算。
接口及原生文件组件验收见 [公共任务受理与恢复](COMPONENT-TASKS.md)。
组合协议实施前的版本化契约见 [组件组合流程 v1](COMPONENT-WORKFLOW-V1.md)。

## 兼容、迁移与验收

第一阶段保持原安装目录、身份文件、签名输入和 HTTP/Socket 协议。
原安装通道由适配器映射进公共操作管理器；新组件不继承 IPSentinel 的
Profile、epoch、Python、Chromium 或数据库内容。

旧回执直接读取，未确认记录继续按原登记补传，不批量重写。
回退到同一协议的旧实现不需转换这些文件；其他数据库或信任迁移仍遵循各自门槛。

必须以无浏览器最小组件验证相同操作管理器及存储，
覆盖精确批准、批准过期、输入变化、取消、重启、断线、未知结果核对和重复回执。
必须验证两个实例独立运行，某组件失败、更新或取消不影响另一组件与心跳。
运行组件的进程和资源边界另在隔离 Linux 上验证，不能用纯内存测试代替。
