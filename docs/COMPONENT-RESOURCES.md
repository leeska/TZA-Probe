# 节点共享资源准入

内部状态版本为 `component-resources/1`，文件位于 Agent 私有组件目录的
`resources/reservations.json`。旧二进制不读取该文件；该文件不修改现有身份、
操作回执、业务数据库或批准协议。

节点容量与单个服务上限分别校验。受信任适配器按稳定实例登记内存、CPU 和进程数；
同一实例重复登记同一上限不重复扣减，改变登记内容必须先经过生命周期收敛。
多个组件共享总容量，不允许通过增加实例越过节点上限。
声明式插件不申请资源，也不创建该账本。
容量检测取物理主机与所有父 cgroup 上限的较小值，并为 Agent 留出 192 MiB 内存
和 64 个进程。每次新准入重新检测；不支持或无法读取的隔离范围拒绝新准入。
这些是常驻服务上限的保守预留，不表示实际 CPU 或内存使用量。

启动清查在所有组件活动开始前完成。已有固定服务按主机上的服务身份登记，
不把业务实例 UUID 当作物理服务身份。观测只读取 systemd 状态及实际 cgroup 限制，
不启动服务、不批准新权限。内核限制未知、无界或清查失败时阻止共享池的新准入，
记录补传与收敛活动仍可运行；周期性复核成功后解除对应清查故障。
已在运行的组件即使超过当前容量也必须入账，随后拒绝新工作。
运行期间的重新观测只保留或增加原预留；缩减与删除须等进程组停止证据。
停止时按实际登记回收，不能因计划中的新上限不同而遗留旧预留。

登记先持久化，再允许启动服务或受理新任务。关闭 Agent、失联、操作超时、健康失败、
更新失败均不释放登记；重启从账本恢复。只有适配器核实整个服务进程组已经停止后，
才能删除与原登记完全匹配的条目。无法核实清理时保留登记。
账本持有进程锁；损坏、身份冲突或存储失败均拒绝新准入，不重置现有记录。

容量下降后允许读取账本和清理旧服务，拒绝超量状态下的新准入。
记录读取、补传、查询已受理任务、取消与暂停不受新任务准入阻塞。
资源预留不替代内核约束；受支持的外部组件仍使用 `componentprocess` 的
内存、CPU 和进程数限制，IPSentinel 继续保留其更严格的内部任务限制。

这里登记的是常驻服务的外层容量，业务逻辑任务仍沿用原任务 ID 及原受理窗口。
连接失败后的重试先查询原任务；不得创建新逻辑任务规避未知状态。
账本本身不启动、不停止服务，也不把一个成功回调视为进程已经清理。

正常 Agent 已将 IPSentinel 启用/激活、业务新提交及恢复接入容量池；
drain 的固定服务停止通过公共监督器核实清理后释放预留。
准入等待发生在主控确认执行开始之前，并在等待后复查批准期限。
旧独立安装器、手工 Socket 接入和全部原生探测尚未统一迁入；
正常组件宿主已补齐没有账本的已运行实例启动清查及精确登记，
但不能据此认定独立旧入口和原生任务已完成迁移。
所有执行入口迁移和组合流程验收前不开放第二个生产运行适配器。
业务任务的参数、健康、查询与取消仍通过现有可信适配器完成。
组合流程和统一资源等待界面另按 [组件组合流程 v1](COMPONENT-WORKFLOW-V1.md) 实施。
