# 组件能力与记录交付：内部契约

状态：2026-11-08 实施中的内部接口。现有公开协议与持久文件保持兼容，
本接口不开放第三方执行入口。

## 能力与权限

公共能力声明分别表达配置、提交任务、取消、暂停和连续记录交付。
各项独立，默认全部关闭；声明式通知和目标集无需声明任何运行能力。
公共层不要求组件具备配置、任务或日志的完整组合。

能力表示适配器支持某项接口，不表示用户已经批准执行。
有效权限仍取签名声明、用户确认、节点本机策略、Agent 支持范围和实际平台的交集。
健康状态、预算、暂停状态和任务授权由各自权威来源校验，
不能用能力声明替代。

IPSentinel 适配器把现有 `hello.features` 映射到公共能力。
其 `assessment`、Profile、epoch 和业务恢复规则不进入公共能力枚举。
现有降级状态下查询、暂停或取消的行为保持兼容，不能因为能力退化禁止安全收敛。

## 有类型的业务回执

公共待确认封装包含登记作用域和有类型的结果。
为兼容已安装节点，内部 JSON 仍使用 `enrollment` 和 `result`；
IPSentinel 安装通道保留原 Go 名称作为实例化别名。
作用域和业务结果的校验仍由适配器提供，公共存储不解释浏览器数据或批准计划。

公共记录确认封装包含可比较的绑定值及 `through_seq`。
绑定由各适配器定义，不强迫其他组件引入 executor instance 或 epoch。
适配器使用不可变的值类型作为绑定，避免使用指向可变状态的指针。

## 记录交付

公共交付器每次只处理一页：

1. 从接收方读取已持久保存的绑定及游标。
2. 从来源读取一页有类型的记录和快照；适配器校验来源身份、快照及业务内容。
3. 检查绑定、起始游标、连续序号、页大小、末尾游标和空页语义。
4. 将记录及快照交给接收方，等待准确绑定和末尾游标的持久确认。
5. 只在持久确认通过后，对来源发送 ACK。

默认页大小为 50，公共上限为 1000；适配器应设置其协议允许的更小上限。
IPSentinel 仍使用 50，不改变已有接口限制。
序号为 0 至 I-JSON 安全整数上限；记录从前一游标加一开始连续排列。
空页只能保留原游标，且不能声称还有更多记录。

接收方写入失败、确认响应丢失、绑定变化或游标不符时，不发送来源 ACK。
ACK 响应丢失时，下一次从接收方已提交的游标继续，
可以用空页重新确认旧游标，不重新生成记录或任务。
接收方仍负责记录去重、内容冲突检查及事务提交；
公共交付器不创造第二份服务器游标，也不自动执行任何业务任务。

来源 ACK 至少覆盖已确认游标，且不得超过安全整数上限。
业务协议可以施加更严格的限制。
来源、接收方及适配器错误保持原类型；公共顺序或确认错误单独分类，
由 IPSentinel 兼容层映射为原来的语义错误。
公共页数限制不代替传输和业务数据的字节限制；
来源适配器仍须在返回公共页前执行原协议的有界读取与 Schema 校验。

## 兼容及验收要求

本次不改变 `hello`、记录、记录确认、安装回执的 JSON 字段、签名内容或数据库版本。
IPSentinel 的作用域授权、原始配置、业务记录、epoch 和 ACK fence 仍经原校验路径。
既有安装回执文件直接读取，不批量迁移、不重新分配身份。

验收覆盖独立的无浏览器记录源、两组件绑定隔离、完整交付顺序、
持久确认丢失和 ACK 丢失后的恢复、跨绑定确认拒绝、页限制与序号边界。
IPSentinel 现有 Socket、业务校验、配置动作和安装通道回归继续运行。
这些内部库测试不代替两种真实运行组件的 Linux 生命周期并存验收。
