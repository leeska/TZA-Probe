# IP 地区防护：官方插件与简化界面

## 产品定位

将 IPSentinel 定位为 TZA-CC 官方「IP 地区防护」节点插件，而非让用户管理独立执行器产品。
插件主界面围绕防送中检测、拉回尝试和干净复测组织。IPSentinel 保留为运行内核名称；
包 ID `ipsentinel-runtime` 和契约身份保持不变，避免破坏已有签名、安装记录与绑定。

防送中表示持续发现地区异常并安排检测，不表示保证地区永不变化。
拉回使用节点已批准的浏览方案，不能承诺改变 Google、Meta 等服务商的内部地区数据库。
实验任务成功不是恢复成功；只有独立干净观测的有效证据才能形成变化判读。
Google 首页跳转消失只说明该跳转信号，不推导其他服务地区或信誉分恢复。

## 页面方案

- 复用 TZA 当前字体、明暗主题与语义色，不另造品牌主题。
- 浅色基准为白 `#ffffff`、正文 `#1d1d1f`、次要文字 `#86868b`；动作与状态使用现有主题令牌。
- 左对齐的功能说明与节点操作区；地区判读是视觉重点，不用技术状态堆满首屏。
- 默认页：节点、服务、最近判读；检测、尝试拉回、干净复测三个动作；排期和记录为次级入口。
- 高级页：版本与安装、授权身份、配置验证、维护和原始记录；安装通道默认折叠。
- 无节点时明确引导安装；无权限、离线、暂停、缺配置、无方案、额度未知或不足时禁用动作并解释。

尝试拉回仍是一次 experiment 任务，不暗中串联复测、恢复控制或创建排期。
提交前再次读取状态并核对授权和配置修订；新身份、新配置必须重新确认。
默认浏览不创建任务、不下载依赖，也不扩大节点系统权限。

## 项目并入建议与边界

建议并入 TZA 的产品与发布体系，但不要把 Python/Chromium 塞进默认 Agent，也不要把
浏览器运行进程并入主控。CC 负责官方审核和签名分发，Probe 负责用户界面、授权与排期，
Agent 负责有限协议管理，节点上的非 root 隔离进程运行 IPSentinel 内核。

代码仓库迁移是下一阶段的独立变更，本轮不移动或删除 `/Users/Apple/code/ipsentinel`：

1. 确认采用 TZA 内的 `official-plugins/ipsentinel` 源码目录还是继续独立仓库、统一发布。
2. 迁移时保留 Git 历史、独立 Python 依赖锁和许可证；契约权威源只保留一份。
3. CC 发行清单绑定可追溯内核提交与依赖摘要，不在两个目录手改协议副本。
4. 保留既有包 ID、持久状态、Profile、预算和 epoch；不自动 adopt 或重新授权旧节点。
5. 正式迁移必须重新验证可复现制品、Linux Chromium、非 root peer、升级回退及旧 Agent 兼容。

当前仍缺首次安装通道自动配置、休眠唤醒和完整启停向导；界面简化不代表这些能力已经完成。
本轮不迁移仓库，不发布新 runtime，不变更生产 CC 既有签名版本，也不自动部署。

## 验证

前端测试覆盖只读浏览、三种任务的用途与阶段、确认后提交、身份/配置变化拒绝、额度与新鲜度、
实验与恢复证据分离及未知状态。真实浏览器检查 390px、桌面、主题、空节点与高级页往返。
页面验证不启动外站浏览器任务，不将 UI fixture 当作真实拉回成功验收。

## 本轮验证结果

- Probe `scripts/pipeline.sh check` 通过，包含全量 Go、竞态、vet 和前端回归。
- `scripts/ip-guard-test.mjs` 覆盖三个动作的协议映射、显式确认、状态与预算限制，以及确认期间配置变化拒绝。
- 原节点插件与安装审批 UI 回归通过，默认浏览不触发下载或任务。
- CC 在临时 PostgreSQL 上通过 `scripts/check.sh`；官方插件详情模板及真实分发审核测试通过。
- 本地真实浏览器验证已配置节点、拉回确认和取消、高级页往返；390px 明暗主题无横向溢出，安装与清单默认折叠。无接入节点的引导由前端回归覆盖。
- 页面证据位于 `/tmp/tza-ip-guard-20261107/`。托管节点使用真实 Python UDS 与准入测试 worker，不启动 Chromium；本轮没有外站实验或真实拉回效果结论。
- 此处记录本地验收范围；生产发布须另行备份、核对签名与在线节点。现有 IPSentinel 仓库和 `0.4.0` 签名包不随页面更新变更。
