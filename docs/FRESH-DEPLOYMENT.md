# 新部署基线

2026-11-09 起，当前开发工作树按全新部署收敛，不再维护历代数据升级与独立安装器接管。
这是一项不兼容变更，不是已发布或已部署的声明。

## Server

- 使用全新数据目录，数据库固定为 `tza-probe.db`，一次事务直接建立 schema 30。
- 历史 schema、更新版本和无版本的非空数据库都拒绝启动，不自动迁移、清空或覆盖。
- 不再自动选择 `tza-v2.db`；旧目录不作为新部署目录使用，避免看起来像数据消失。
- 网络历史预聚合从首次写入开始维护，不再保留历史回填表、后台回填与等待分支。
- 当前基线的数据库备份仍可恢复到当前基线；旧备份不能通过改版本号变成新库。

## Agent

- 由运维保留并迁移既有节点凭据，或为全新节点重新接入。
- Agent 不再包含节点组件管理器、审批、暂存、暂停和权限提升入口，只保留探测、升级与受限出口。
- 不再读取 `/etc/tza-probe/runtime-installer.json`，旧配置字段应由项目外迁移脚本移除。
- 旧主机上的 IPSentinel 服务与数据由运维备份并下线，不由产品首启自动接管。

## 配套 CC

CC 同步改为全新 PostgreSQL schema 13，直接加载 `internal/store/schema.sql`。
旧的 `schema_migrations` 数据库不会自动升级，需使用新的数据库或空 schema。
初始化采用事务级咨询锁，多个实例并发启动只能初始化一次；失败回滚后可重试。

## 运维边界

此次源码清理不执行停机、删库、撤销节点、密钥轮换、签名或生产部署。
新部署仍需使用可信签名密钥，不恢复已失密的 Agent 升级信任根。
在确认新实例可用之前，保留原数据、制品、签名材料和回执的离线备份。
