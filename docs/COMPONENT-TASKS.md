# 公共任务受理与恢复

`componenttask` 负责 Agent 内部的任务查重与受理顺序，不建立第二套排期或业务预算。
逻辑任务、稳定幂等请求和投递尝试分别标识；公共代码不生成替代 ID。
载荷、作用域、配置修订、能力、业务结果和后端存储仍由可信适配器校验。
声明式插件不实现该接口。

收到一次投递后先查询原逻辑任务。已经受理的任务即使原窗口过期、当前资源不足或暂停，
也只读取并确认原任务，不重新提交。
只有后端明确报告原任务未知，才核对资格和原受理窗口，使用原幂等请求提交。
查询失败、提交结果未知、错误回执或作用域不符均不生成新任务，也不伪造成功。
准入资格检查后的窗口过期仍拒绝新提交。
取消能力可选：只查询和取消原逻辑任务，保留稳定的取消请求及投递身份。
原任务未找到与任务已经停止分别表达；公共层不把缺失记录或取消回执视为进程清理证据。

后端须以稳定逻辑任务及幂等键持久去重；公共层不能代替后端的事务或执行隔离。
后端返回的记录须经适配器校验，不能只凭一个无错误响应确认受理。
有界请求使用调用方上下文；实际任务超时、取消及进程清理由原执行适配器和公共进程监督器完成。
取消成功必须以适配器的清理证据为准，不以关闭一次网络调用视为任务已经停止。

IPSentinel 已接入原任务查询/受理及取消路径，保留原目标、实例、epoch、配置、健康、
请求窗口、RPC 错误和租约协议。公共层没有 Python、浏览器、Profile 或 epoch 依赖。
原生探测的既有 Job/Result 协议继续由 Agent 原生执行和取消；
本文不表示其全部路径已使用新的持久资源池，也不表示组合暂停/移除已实现。

## 生命周期任务收敛

`ipsentinel.Quiescer` 供可信生命周期适配器收敛原任务：先确认原 binding，
使用由原批准计划派生的稳定暂停请求，按原逻辑 Job ID 查询，只有明确批准取消时才取消，
再逐页持久补传并确认记录。取消请求按原暂停请求及 Job ID 确定生成；
取消回执必须保持原 Run ID、实例和 epoch。未知受理保留待核对，不换 ID 重提，
也不将“没查到”当作进程已经停止。

`Synchronizer.SyncRecords` 只补传，不领取或执行主控动作；普通 `Sync` 保持原行为。
主控仅在派发暂停或持久维护所有权存在时，经节点凭据返回其当前 binding 下
已尝试且未取得终态的原任务，最多 256 项；未投递、已拒绝及终态任务不重新取消。
清单只读，不修改原租约、请求或结果。过期快照、权限撤销、其他节点或身份不符均拒绝。
跨非 root peer 的新增操作保留结构化 RPC 拒绝，原任务未知与连接失败不会被混同。
原有 Hello、暂停及配置应用的 peer 返回格式保持不变。

正常 Agent 的既有 drain 路径已接入原记录补传和任务收敛，固定服务停止仍由
公共监督器验证整个进程树后才释放资源。仅当暂停、无活动任务、没有 draining、
源 ACK 和主控持久 cursor 都等于最新记录时才能进入停止步骤。
旧 drain 批准没有取消任务语义，仍只等待原任务自然完成；不能借本次底座扩展旧批准权限。
这不是完整组合暂停/移除界面或迁移验收；该工作仍按组合流程契约继续。

`Quiescer.Inspect` 专供只读效果核对，要求原 managed 身份、原任务终态及双方最新游标一致，
不会发送 pause/cancel、记录提交或 ACK。组合暂停的可信宿主可将仍待完成的原收敛步骤
标记为 `in_progress`；公共 Runner 只在后端明确实现 continuation 且证据/当前授权/资源
再次通过时续行同一持久尝试。它不是泛化重试许可，停止、安装等未知步骤不获得此权限。
