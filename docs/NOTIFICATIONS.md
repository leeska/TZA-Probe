# 事件通知与 Telegram 模板

在后台“告警与通知”配置 Telegram Bot Token 和 Chat ID 后，可点击测试通知检查连接。事件支持节点离线、到期续费、流量额度、达量降速、CPU 和内存使用率六类提醒。

## 消息格式

Telegram 使用纯文本，不解析节点名称中的 HTML 或 Markdown。消息按状态、节点身份、事件数据和时间分段，示例：

```text
TZA Probe · 🔴 告警触发
类型：CPU 使用率
节点：JP-NoSla-Gen2
节点 ID：节点唯一标识

分组：JP
地区：日本

当前 CPU：95.2%
触发条件：CPU ≥ 90%，持续至少 5分钟
指标采样：2026-10-13 15:30:00 UTC
规则来源：全部节点
重复提醒间隔：30分钟
本次条件持续：5分钟

事件时间：2026-10-13 15:30:00 UTC
事件编号：#123
```

- 节点 ID 用于区分同名节点，事件编号用于核对后台记录和通知重试。
- 已填写的分组、地区随事件记录；未设置时不打印空行字段。
- 时间统一明确标注 **UTC**，事件时间是事件产生时间，指标采样是 Agent 最近上报时间。
- 数据在事件产生时写入数据库。延迟投递或重试使用同一份快照，不用投递时的新指标替换历史值。
- “本次条件持续”从服务端首次检测到条件满足时计算，包含规则设定的等待时间；它不等于未知的实际故障起点。首次立即触发的事件省略零秒持续时间。

## 各类事件包含的信息

| 类型 | 事件数据 |
| --- | --- |
| 节点离线 | 最后上报时间、未上报时长、45 秒离线判定和额外等待时间；从未上报的节点显示添加时间、首次接入宽限和安装排查提示 |
| 到期续费 | 到期时刻、精确剩余或已过期时长、提醒提前天数；已设置价格时显示金额、币种和周期，免费节点明确标记 |
| 流量额度 | 本周期已用量、额度、已用百分比、触发百分比、统计口径与计费周期 |
| 按额度降速 | 已用量、额度、百分比、统计口径、周期和商家声明的限速 |
| 按平均带宽降速 | 当前窗口平均带宽、配置窗口小时数、实际有数据的小时数和触发阈值 |
| CPU 使用率 | 当前 CPU 百分比、阈值、持续要求和采样时间 |
| 内存使用率 | 当前内存百分比、已用与总容量、阈值、持续要求和采样时间 |

流量单位采用十进制 KB / MB / GB / TB，与节点额度配置一致。降速状态是面板根据商家规则和用量推算的结果；消息明确提示实际限速仍需确认，不把推算当成测速证据。

到期提醒按实际时刻区分剩余与过期：过期 6 小时会显示“已过期：6小时”，不会因为不足一天而显示“今天到期”。

## 解除和重复提醒

解除消息使用中性的“⚪ 告警解除”，并带具体原因和当时的数据。例如：

```text
TZA Probe · ⚪ 告警解除
类型：CPU 使用率
节点：JP-NoSla-Gen2
节点 ID：节点唯一标识

解除原因：告警条件已解除
当前 CPU：20.5%
当前阈值：90%
本次条件持续：10分钟

事件时间：2026-10-13 15:35:00 UTC
事件编号：#124
```

如果节点离线使 CPU / 内存无法继续评估，会说明“节点离线或指标不可用，使用率告警停止评估”，不宣称使用率已经恢复正常。如果提醒规则被删除或不再覆盖节点，会说明该节点当前未启用此类提醒，即使当前读数仍高也不会假报健康恢复。

持续异常的重复通知在正文注明“提醒状态：异常仍持续（重复提醒）”，更新事件发生时的读数与条件持续时长。网络失败导致的同一事件重试仍使用原事件编号和原快照，不作为新的重复提醒。

连接测试消息只包含测试状态、Telegram 通道、说明和事件时间；不显示空节点字段或无意义的事件编号 0。

## 投递与兼容性

- 同一时间启用一个通知渠道：Telegram 或 Webhook。
- 失败使用指数退避重试，最多 10 次；只补发 24 小时内的未投递事件。查看后台事件列表中的发送次数与错误原因。
- Webhook 保持 `{ "version": 1, "event": { ... } }` 的字段结构；`event.message` 与后台记录一样包含分行数据，接收端按 `event.id` 去重。
- 旧事件保留原有正文，新事件采用补全后的快照格式；无需数据库迁移。
