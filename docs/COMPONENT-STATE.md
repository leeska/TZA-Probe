# Agent 公共配置引用与持久回执

状态：2026-11-08 已接入现有运行组件安装通道。本文描述内部公共库，
不增加公开组件协议、第三方执行权限或安装入口。

## 配置修订

`internal/componentproto.ConfigRef` 表示配置修订及规范配置摘要，
`ConfigReceipt` 表示应用后的引用及是否发生改变。
IPSentinel 的同名 Go 类型通过别名保持兼容，JSON 字段仍为
`revision`、`sha256`、`config` 和 `changed`。

配置引用要求修订在 1 至 I-JSON 安全整数上限内，摘要为 64 位小写十六进制。
`ValidateApplied` 校验准确摘要和预期修订：发生改变时递增一次，
未发生改变时保留预期修订。达到整数上限的未变配置仍可确认，
需要递增的应用必须拒绝。

Agent 动作接入和 Probe 回执存储使用相同规则。业务配置内容、摘要生成前的业务校验、
同配置请求的幂等行为及配置冲突响应仍由适配器负责。
公共库不自动分配配置修订，也不为业务配置建立第二份存储。

## 本机持久回执

`internal/componentstate.FilePending[T]` 接收有类型的记录及适配器校验函数，
提供私有目录、稳定身份、操作锁、待确认记录和已确认归档。
公共库不导入 IPSentinel、浏览器、运行组件安装器或主控 HTTP 客户端。
`Pending[Enrollment, Result]` 和 `Journal[T]` 已承接通用的有类型回执封装与存储接口，
原 `RuntimePending`、`RuntimeJournal` 保留为兼容别名。
记录交付及能力接口另见 [组件能力与记录交付](COMPONENT-DELIVERY.md)。

每个组件实例使用独立的私有目录；目录由可信 Agent 配置选择，
不能直接使用未审核包提供的宿主路径。一个目录有一个待确认操作槽：

| 文件 | 作用 |
| --- | --- |
| `identity` | 稳定 UUID，已有身份不会因读取、重启或升级重新生成 |
| `channel.lock` | 同一实例的非阻塞操作锁 |
| `pending.json` | 等待主控持久确认的操作记录 |
| `receipts/<UUID>-<state>.json` | 确认后的本机证据 |

适配器校验函数负责记录的作用域、身份、受支持状态和业务字段。
公共库再次检查操作 UUID 和有界状态名，避免归档文件名越界。
保存和读取都运行校验；损坏或未知记录保留在原处，等待显式恢复。
已存在未确认记录时，只允许同一操作推进，其他操作不能覆盖它。

所有完整读改写事务由调用者持有 `Lock`，包括加载、同一操作的进度写入、
发送和确认后的清理。`Save`、`Load` 和 `Clear` 不重复获取锁，
以兼容安装通道已经持有的跨步骤锁。`Identity` 自行获取锁，
因此应在安装事务之外调用。已持锁的版本刷新使用只读 `ReadIdentity`，
不重复取锁；身份缺失、损坏或与当前登记不符时拒绝刷新，不生成替代身份。
不同目录的锁互不阻塞。

写入采用 0600 临时文件、文件同步、原子替换和目录同步。
读取拒绝符号链接、非普通文件、其他用户可读写的文件、错误属主及超过
128 KiB 的记录。目录要求私有且属于当前 Agent 用户。
已确认归档先完成同步，随后才移除待确认记录并同步目录；
归档失败时保留待确认记录。

持久确认的真实性由协议适配器判断。`Clear` 本身不联系主控，
只有接收到匹配的主控持久确认之后才能调用，不能将“发送成功”
或“收到任意 HTTP 200”当作确认。断线后使用原操作 ID 和原作用域重放，
不能通过生成新 ID 重新执行。

## 兼容与回退

这是内部实现抽取，没有引入新线协议或数据库修订。
现有安装通道的 `FileRuntimePending` 保留原 Go 接口，
将文件操作交给公共存储，将 enrollment 和状态校验保留在安装适配代码。
旧 `identity`、`pending.json` 和 `receipts` 的路径及 JSON 结构不变，
加载时不迁移、不改写、不清空旧文件。

回退到抽取前的同一兼容版本无需转换这些文件；仍应保留未确认记录和归档。
这不替代本轮其他改动的回退条件，例如 SQLite schema 27 的数据库备份恢复要求，
也不解除旧 Agent 升级密钥的撤销限制。

## 本轮验证范围

公共库使用不含浏览器和 IPSentinel 类型的组件记录验证独立身份、并行锁、
重启后读取、同操作推进、错误操作确认、禁止覆盖未确认记录、
确认归档失败保留记录，以及私有权限、路径和有界严格解码。

安装通道回归使用旧格式文件验证原身份和记录能直接读取、确认并归档；
既有丢失确认、旧作用域重放和禁止重复执行用例继续覆盖通道行为。
版本刷新通过真实 `RuntimeInstaller.Sync` 调用链验证持锁刷新、原身份保持，
以及本机身份丢失或被替换时停止刷新。
共享配置校验覆盖增量与不变回执、错误摘要、修订越界及整数上限。

Debian 13 amd64 上以专用非 root QA 用户运行公共存储的 7 项测试，
以及 Agent 持锁刷新、旧作用域确认和 journal 兼容相关的 5 项测试，全部通过。
两个临时 systemd 单元成功退出并回收，未替换生产 Agent；
生产 `tza-agent.service` 保持 active，PID 前后均为 31805。
Linux amd64 与 arm64 Agent 测试二进制均可交叉编译；arm64 未进行现场执行。
证据保存在 `/tmp/tza-component-foundation-evidence-20261108/`。
本次源码的完整 `pipeline.sh check` 通过，包含 Go 全量、竞态、vet、
前端回归及一次性服务 DOM 检查；DOM 检查不覆盖视觉布局。
角色包生成器自检因本机缺少 Pillow/numpy 跳过。
