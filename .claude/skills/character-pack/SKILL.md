# 生成二次元角色包

角色包是 `"type": "characters"` 的主题包（格式见 `docs/THEMES.md` 的「角色包」一节）。工具在
`tools/character-pack/make_pack.py`，说明在同目录的 `README.md`。你负责设计角色、把关每一步的图，脚本负责出图与处理。

## 1. 确定要做哪些地区

- 问用户要覆盖哪些地区；用户说「按后台的来」时，读公开节点列表里的 `region`（`GET <面板地址>/api/v1/nodes`，
  或用户已配置的 MCP `list_nodes`），去重后列给用户确认。
- 已有角色的地区（用户说过的、或后台已装的角色包）先问要不要重做。
- 角色只按地区区分：**同一地区不同商家共用一个角色**，商家名由卡片上的名牌显示。不要按商家出图。

## 2. 设计角色，先给用户过目

每个地区一个角色，写进 `pack.json`（格式见 README）。`design` 用英文，写清：发型与发色、眼睛、服装、1–2 个配饰、气质。

设计规则：
- **轮廓要能一眼区分**：每个角色至少一个独有的轮廓特征（发型、发色、帽子 / 兽耳、服装款式），同一包里不撞，
  也别撞内置角色：通用角色（深棕长直发、白衬衫、藏青百褶裙）、日本（银白长直发 + 猫耳 + 紫瞳 + 水手服）、
  德国家人云（蜂蜜金麻花冠 + Dirndl）、美西 VMISS（栗棕双马尾 + 电蓝挑染 + 白色连帽衫）、
  洛杉矶搬瓦工（琥珀棕高马尾 + 工装背带裤）。
- **地区感靠服装、配饰、配色**（当地的传统纹样、城市气质、代表色），不要写国旗、地图、地标文字。
- **不写任何文字、logo、商家名**；需要铭牌就写 blank name tag。
- 原创角色：不要模仿现有动漫角色或真人；服装得体。
- 设定里不用写构图（全身、捧白牌、白底、牌子位置），脚本的提示词里已经有了。

把设定整理成一张表（地区 / 外形要点 / 独有特征 / 配色倾向）给用户确认。**出图要花钱，用户确认之前不要调接口。**

## 3. 配置图像接口

- 需要一个兼容 OpenAI `/chat/completions`、能返回图片的接口（推荐 Nano Banana Pro：`gemini-3-pro-image`）。
- 让用户提供接口地址和密钥，只通过环境变量传给脚本：`TZA_IMAGE_API_BASE`、`TZA_IMAGE_API_KEY`、`TZA_IMAGE_MODEL`。
  **不要把密钥写进仓库、设定文件或任何会被提交的文件**；需要落盘时放到临时目录并 `chmod 600`。
- 密钥如果是在对话里贴出来的，完成后提醒用户去平台作废、换一把新的。
- 依赖：`python3 -m pip install pillow numpy`（系统 Python 装不了就建一个 venv）。

## 4. 先出一张，确认再批量

工作目录放在临时目录或仓库外，别把原图、zip 提交进仓库。

```sh
python3 tools/character-pack/make_pack.py generate pack.json --work <工作目录> --only <第一个角色 id>
```

用 Read 看 `<工作目录>/raw/<id>.png`：全身、正面、双手捧一块**空白**白牌、白底、没有文字。有问题就改 `design`
再 `--force` 重画；没问题再跑其余角色（不带 `--only`，已有的会跳过，不重复花钱）。

## 5. 处理与检查

```sh
python3 tools/character-pack/make_pack.py build pack.json --work <工作目录> --out <工作目录>/<包 id>.zip
```

用 Read 看 `<工作目录>/preview.png`：红框应正好框住牌子外沿，青色只覆盖压在牌子上的手指。
脚本报「牌子位置不对」「闭眼帧没对齐」、或预览里框歪了，就对那个角色 `generate --only <id> --force` 重画后再 build。
`palette` 是自动取的，颜色不对味可以在设定里写死再 build（不用重画）。

## 6. 交付

- 把 zip 交给用户：后台「主题 → 上传主题包 / 角色包」（面板要先装好二次元主题）。用户给了面板地址和管理员 token 并要求你代传时，
  `POST <面板地址>/api/v1/admin/themes`，请求体就是 zip，`Content-Type: application/zip`，`Authorization: Bearer <token>`。
- 提醒用户：角色按节点的「所在地区」自动匹配（与 `regions` 逐字一致），节点设置里也能手动指定；
  节点的「商家」字段会显示在看板上沿的名牌上；同一 `id` 的角色包再传一次即覆盖升级。
